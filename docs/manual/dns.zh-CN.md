# DNS

DNS 功能把域名解析过程和自定义 Hosts 映射放在同一个入口中。你可以查看解析历史、识别失败或变慢的查询，也可以把某个域名临时映射到指定地址，用于联调和环境切换。

## 两个组成部分

### Hosts

Hosts 是主动配置的域名映射。每条记录包含域名、目标地址以及可选备注；保存后会写入 Lemon 的 DNS 配置，由运行时在后续查询中使用。相同域名不能重复创建，修改或删除后要重新触发查询才能观察新结果。

### DNS Query History

查询历史记录实际发生过的 DNS 事务，包括解析动作、解析器信息、耗时、CNAME 链和异常状态。历史视图支持搜索与筛选，常用筛选包括全部、需要关注、FakeDNS 和包含 CNAME 的记录。

## 添加 Hosts 映射

1. 打开 DNS 设置并进入 **Custom Hosts**。
2. 新建映射，填写域名和目标地址；域名不要带协议头或路径。
3. 确认目标是合法的 IP、主机名或当前版本支持的地址格式。
4. 保存并等待配置应用完成。
5. 让目标 App 重新发起请求，再到查询历史中核对实际动作。

Hosts 映射只影响匹配到该域名的解析结果，不会修改 HTTP 请求中的 URL，也不会自动替换已经建立的连接。已经缓存的解析或长连接可能需要等待过期、重启请求方或重新建立连接。

## 阅读查询历史

一条记录通常可以帮助你回答：

- 目标域名解析到了什么结果。
- 查询使用了哪个解析器和传输方式。
- 是否命中 Hosts、FakeDNS 或被拦截。
- 是否发生了 CNAME 跳转。
- 是否发生 fallback、错误或明显偏慢。

优先从同一域名的多条记录比较，而不是只根据一次查询做判断。查询失败可能来自网络、上游解析器、Hosts 配置或目标域名本身。

## 常见动作含义

| 结果 | 含义 |
| --- | --- |
| Pass-through | 按正常解析链路继续处理 |
| Hosts | 使用自定义 Hosts 映射 |
| Blocked by Hosts / Rejected | 被 Hosts 规则或拒绝策略阻断 |
| FakeDNS | 返回用于调试链路的虚拟解析结果 |
| Fallback | 首选解析方式失败后使用备用方式 |

## 排查顺序

当请求没有到达预期服务器时，先检查域名是否拼写正确，再看 DNS 历史中是否有新查询和实际结果。若 Hosts 已保存但没有新记录，可能是连接复用或缓存；若有查询但结果不符，检查映射目标、规则状态和当前 TUN / VPN 是否加载了新配置。

DNS 配置会改变真实设备的网络行为。完成临时联调后，应删除或停用不再需要的 Hosts 映射，避免后续请求继续被导向测试地址。
