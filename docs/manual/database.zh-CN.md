# 数据库

数据库页面用于查看 Lemon 本地 SQLite 数据库的存储概况、表结构和表数据，并在受控场景下执行 SQL。它主要面向诊断持久化状态和关联调试记录，不是日常业务数据管理工具。

## 页面内容

数据库概览通常包括：

- 数据库存储总大小。
- 当前表列表及记录数量。
- 已应用的数据库迁移。
- 进入单表查看和 SQL Console 的入口。

进入表详情后可以查看列名、类型、是否允许 NULL 等结构信息，并读取表中的记录。先看表结构再写查询，避免依赖猜测的列名或旧版本结构。

## 查询原则

建议从只读查询开始：

```sql
SELECT *
FROM your_table
LIMIT 20;
```

然后逐步增加条件和排序，控制返回规模。表名和列名应以当前页面显示的结构为准；上面的 `your_table` 只是占位符，不是 Lemon 固定表名。

对大型表，优先使用明确列、`WHERE` 和 `LIMIT`。查询结果用于诊断时，注意时间字段、分页和当前运行时是否仍在写入数据。

## 写入风险

SQL Console 允许的语句和权限以当前 App 版本为准。任何 `UPDATE`、`DELETE`、`INSERT`、DDL 或迁移操作都可能破坏请求记录、配置或运行时状态：

1. 先查询确认目标行。
2. 记录原值或创建可恢复副本。
3. 尽量使用精确的主键条件，不要使用没有 `WHERE` 的更新或删除。
4. 执行后重新查询，确认影响范围。
5. 必要时重启或重新加载相关运行时，验证应用层是否接受新状态。

不要为了“修复”表结构直接删除迁移记录，也不要把不同版本的数据库文件互相覆盖。迁移状态属于 Lemon 的内部一致性边界。

## 与其他功能的关系

请求、DNS、重放和脚本运行记录可能分散在不同表中。数据库页面适合回答“数据是否持久化、数量是否合理、迁移是否完成”等问题；要理解一条请求的网络语义，仍应回到请求详情或对应功能页面。

数据库内容可能包含完整 URL、请求体、Cookie、Token 和本地路径。复制 SQL 结果给其他人或 AI 前先脱敏，完成临时诊断后清理不再需要的导出内容。
