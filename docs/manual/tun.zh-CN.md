# TUN

TUN 是 Lemon 接入设备网络流量的虚拟网络接口。Lemon 通过 Packet Tunnel 将设备流量引入自己的 TCP/IP 处理链路，再交给请求、DNS、MITM、重写和其他调试能力处理。

## TUN 负责什么

TUN 解决的是“流量如何进入 Lemon”。它不是一个独立的请求编辑器，也不是仅用于显示统计数据的页面。没有有效的 TUN / VPN 链路，其他功能可能没有新的请求或 DNS 记录可供查看。

## 运行状态

TUN 页面可以查看：

- Packet Tunnel 的实时内存使用情况。
- 虚拟接口的 IPv4 地址、Netmask 和 MTU。
- 当前生效的 DNS 解析器数量、传输方式和 fallback 策略。
- 是否显示实时内存浮窗。

这些信息用于判断运行时是否已经启动以及当前配置是否被应用。接口地址和 MTU 是诊断信息，不建议在没有明确网络方案的情况下手工修改。

## 建议的启动检查

开始抓包前按以下顺序确认：

1. 打开 TUN 页面，确认运行状态正常。
2. 检查当前生效 DNS 是否符合本次测试预期。
3. 回到请求列表，让目标 App 重新触发网络操作。
4. 如果仍然没有请求，先用一个已知的普通 HTTP / HTTPS 访问验证链路。
5. 确认后再启用 MITM、Rewrite 或 Hosts，减少同时变化的配置数量。

## 流量没有出现时

检查目标 App 是否使用了不经过系统代理的链路、是否有其他 VPN / 网络扩展占用路径，以及 App 是否真的发起了请求。对于 HTTPS，TUN 能接收连接不代表已经完成证书信任；对于 DNS，查询是否可见还取决于当前解析配置和缓存。

## 资源与安全

抓包、Body 缓冲、重写和脚本都会增加 Packet Tunnel 的工作量。调试大文件或高流量场景时，注意实时内存和列表规模，及时清理无关记录。停止测试后关闭 TUN / VPN，避免临时代理、Hosts 或重写规则继续影响设备的日常网络。
