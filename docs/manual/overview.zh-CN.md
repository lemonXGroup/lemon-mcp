## 00 Lemon 总览

Lemon 是一款面向真实 iPhone 的本地网络调试工具。它把流量捕获、请求分析、HTTPS 检查、请求重写、请求重放、DNS 调试、自动化脚本和可扩展模块放在同一个 Console 中，适合定位客户端网络问题、构造可重复的测试条件，以及验证接口在不同网络环境下的行为。

Lemon 的核心工作方式可以概括为：

```text
连接真实设备 → 捕获网络流量 → 定位问题 → 选择调试手段 → 验证结果 → 清理现场
```

## Lemon 能解决什么问题

不同问题通常对应不同的工具。先判断你要观察、修改、重复执行还是自动化，再选择功能会更高效。

| 功能 | 主要作用 | 适合处理的任务 |
| --- | --- | --- |
| 请求 | 捕获、搜索、筛选和查看 HTTP / HTTPS 请求 | 定位接口、状态码、请求头、响应内容和耗时问题 |
| MITM | 在受信任证书配置下检查 HTTPS 内容 | 查看加密请求的明文 Header、URL 和 Body |
| 重写 | 在请求或响应经过 Lemon 时修改内容 | Mock 接口、切换环境、注入调试 Header、替换响应 |
| 重放 | 保存请求并再次执行 | 复现接口问题、比较修改前后的服务响应 |
| DNS | 查看 DNS 查询并管理 Hosts 映射 | 验证域名解析、临时指向测试服务器或本地地址 |
| TUN | 通过本地 TCP/IP 流量接入 Lemon | 捕获和检查设备上的网络流量 |
| 脚本 | 按计划或 Rewrite 阶段执行受限 JavaScript | 周期检查、自动化处理、请求和响应变换 |
| 模块 | 安装带有独立界面的本地扩展 | 将重复的调试流程制作成可复用工具 |
| 文件 | 浏览、编辑和分享共享存储中的文件 | 管理 Mock 数据、脚本资源和调试产物 |
| 数据库 | 查看和管理 Lemon 使用的本地 SQLite 数据库 | 诊断持久化状态和关联调试记录 |
| 局域网代理 | 将 Lemon 代理共享给局域网设备 | 调试没有直接运行 Lemon 的其他设备 |
| 远程控制 | 提供浏览器可访问的控制端点 | 从 Mac 或其他受控客户端操作 Lemon |
| AI 助手 | 连接支持的 AI 集成 | 辅助分析请求、日志和调试过程 |

这些功能不是互相独立的页面，而是一条调试链路中的不同环节。例如，可以先在 **请求** 中找到接口，再用 **重写** 替换响应，最后用 **重放** 验证客户端是否正确处理结果。

## 一条典型的调试流程

### 1. 连接并确认设备状态

Lemon 的主要目标是正在运行 Lemon 的真实 iPhone。开始前确认设备已经连接，网络路径已经接入 Lemon，并查看 VPN / TUN、WebControl 和相关运行状态。没有设备流量时，后续列表为空不一定代表功能故障。

### 2. 配置 HTTPS 检查

如果要查看 HTTPS 的请求或响应内容，需要先完成受信任的证书配置，并确认目标 App 接受该证书。证书配置、App 的证书绑定和未解密的流量都会影响可见内容；出现空 Body 时，不要直接判断为服务端没有返回数据。

### 3. 捕获并缩小范围

在 **请求** 中先用域名、路径、方法或状态码缩小范围，再打开单条请求详情。优先记录请求时间、URL、请求头、响应状态、Body 是否可读，以及是否存在重定向、压缩或解码状态。

### 4. 选择最小的调试动作

- 只想观察结果：使用请求详情、日志和数据库信息。
- 只想临时修改一次：使用重写规则。
- 想重复同一个请求：保存后使用重放。
- 想影响域名解析：使用 DNS / Hosts。
- 想周期性运行逻辑：使用脚本。
- 想封装一个完整工具：使用模块。

调试时尽量只改变一个变量。规则越具体、权限越少、修改范围越小，结果越容易解释和回滚。

### 5. 验证并清理

修改后让客户端重新触发同一场景，比较请求和响应的实际变化。确认问题定位完成后，停用临时 Rewrite、Hosts 映射、VPN 或调试脚本，清理不再需要的抓包和敏感数据，避免后续测试继续受到旧配置影响。

### Lemon MCP：让 AI 参与调试

Lemon MCP 是面向 AI Agent 的 MCP 服务。它负责发现设备、调用 Lemon 的远程控制接口、整理返回结果和管理部分自动化资源；网络解析、TLS 处理和抓包数据仍由 iPhone 上的 Lemon 负责。

MCP 适合把多个 Console 操作串成一个可复核的调试剧本，例如：读取设备状态、搜索请求、展开 Body、关联日志、验证 Rewrite 运行状态，再根据用户授权执行一次重放。MCP 返回“请求已接受”不等于运行时已经加载或客户端已经完成验证，涉及写操作时要分别确认持久化结果、运行时状态和最终请求结果。

## 功能之间如何配合

### 观察：请求、DNS、日志和数据库

先使用请求列表和详情建立事实，再用 DNS、日志或数据库补充上下文。列表摘要适合快速定位，详情和原始 Body 适合确认具体内容；不要只根据一条预览或一个状态字段下结论。

### 修改：MITM、重写和 Hosts

MITM 解决“能否看见 HTTPS 内容”，重写解决“经过 Lemon 的内容如何临时改变”，Hosts 映射解决“域名应该解析到哪里”。三者作用层次不同，出现问题时先确认目标流量是否经过对应层。

### 复现：重放和脚本

重放适合一次性复现已保存请求，脚本适合有计划地重复执行逻辑。脚本运行在受限环境中，不能按 Node.js 程序的方式使用任意文件系统、npm 包或外部网络；具体入口函数和权限以脚本章节和当前 iOS validator 为准。

### 扩展：模块

模块适合将多个操作组合成一个带界面的本地工具。模块可以拥有自己的声明式 UI、Core ESM 逻辑、语言包和受控能力，但它仍然由 Lemon iOS 宿主加载和运行。制作模块时，应使用公开的 [`lemon-module`](https://github.com/lemonXGroup/lemon-module) 工具完成初始化、校验、测试和打包。

## 安全和数据边界

- Lemon 主要处理用户设备上的本地调试数据；抓包 Body、Cookie、Authorization、Token 和数据库记录都可能包含敏感信息。
- 安装第三方模块、导入脚本包或启用 AI 连接前，先检查来源、能力声明、目标地址和日志行为。
- 重放会向目标服务重新发起请求，可能产生真实副作用；执行前确认请求对象、环境和用户授权。
- `execute_raw_sql`、删除抓包、清空日志、修改 DNS、发布规则和启停模块都应被视为有影响的操作。
- 共享诊断结果前，清理设备地址、账号信息、Token、Cookie、请求正文和本地路径。

## 如何选择入口

| 你的目标 | 推荐入口 |
| --- | --- |
| 我想先确认设备有没有正常工作 | Console 的运行状态、TUN / VPN 状态和环境信息 |
| 我想找到某个接口请求 | 请求列表的搜索和筛选 |
| 我想临时替换接口响应 | 重写 |
| 我想再次执行一个请求 | 重放 |
| 我想定期执行诊断逻辑 | 脚本 |
| 我想做一个带 UI 的调试工具 | 模块和 `lemon-module` |
| 我想让 AI 协助分析真实设备 | Lemon MCP |
| 我想查看某个能力的细节 | 用户手册对应章节和 Markdown 源码 |

当不确定从哪里开始时，先确认设备状态，再从请求列表建立最小事实集合，最后选择一个最小范围的修改或自动化动作。这样可以减少误判，也方便在出现问题时回到上一个已验证状态。
