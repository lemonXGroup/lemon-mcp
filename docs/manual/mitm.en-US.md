# MITM

MITM inspection lets Lemon decrypt and inspect HTTPS transactions using a trusted root certificate. It answers whether encrypted connection content can be seen; it does not replace Requests, Rewrite, or Replay.

## Requirements

HTTPS inspection normally requires all of the following:

1. Lemon has generated a CA certificate for the device.
2. The certificate has been exported and installed as an iOS configuration profile.
3. Lemon CA is enabled under **Settings > General > About > Certificate Trust Settings**.
4. The target app accepts the certificate and its traffic passes through Lemon's TUN / VPN path.

The certificate is a local debugging credential. Do not upload private keys or exported certificate files to untrusted locations. Remove certificates and debugging material that are no longer needed.

## Configure it

### Generate or inspect the CA

Open certificate settings and inspect the current status. Use **Generate Certificate** when there is no certificate. With an existing certificate, use **Export Certificate** to produce the installation file. Use **Regenerate CA** only when the certificate is lost, damaged, or the trust chain must be rebuilt, because regeneration invalidates the old chain.

### Install and trust it

Install the exported profile through iOS, then enable full trust for Lemon CA in the system certificate trust settings. Return to Lemon and use **Check Trust** to verify that iOS reports the root as trusted.

“Generated” and “trusted by the system” are different states. The first means Lemon has a certificate; the second means iOS can validate site certificates generated by Lemon.

### Verify the path

After configuring trust:

1. Start TUN / VPN.
2. Trigger a known HTTPS request in the target app.
3. Open it in Requests and inspect its headers and body.
4. If only connection information is visible, check certificate pinning, the target domain, and whether the protocol supports inspection.

## Pinning and other limits

Some apps pin a server certificate or public key. They can reject Lemon's certificate even when iOS trusts Lemon CA. You may see a failed connection, an incomplete request, or no decrypted body. System trust does not mean every app can be inspected with MITM.

MITM also cannot recover business fields that the client encrypts, compresses, or encodes itself. Check Content-Type, Content-Encoding, and the response status before deciding whether a body should be readable.

## Security boundary

- Install debugging certificates only on devices and services you own or are authorized to test.
- Turn off VPN / TUN and remove unnecessary trust configuration after the test.
- Request bodies, cookies, tokens, and certificate files can be sensitive.
- After regenerating a CA, reinstall and trust the new certificate before capturing again.

## Troubleshooting

| Symptom | First check |
| --- | --- |
| Lemon reports not trusted | iOS trust settings and whether the correct Lemon CA was selected |
| HTTPS requests are not recorded | TUN / VPN, the app's traffic path, and network permission |
| A request exists but the body is unreadable | Content-Encoding, binary content, pinning, or protocol type |
| Everything fails after regeneration | Whether the new profile was installed and trusted |
