# MITM

MITM（中间人检查）让 Lemon 在受信任的根证书基础上解密并检查 HTTPS 事务。它解决的是“能否看到加密连接内容”，并不替代请求列表、重写或重放。

## 使用前提

要检查 HTTPS 内容，通常需要同时满足：

1. Lemon 已生成当前设备使用的 CA 根证书。
2. 根证书已经导出并安装为 iOS 配置描述文件。
3. 在“设置 > 通用 > 关于本机 > 证书信任设置”中打开 Lemon CA 的完全信任。
4. 目标 App 没有拒绝该证书，且它的请求经过 Lemon 的 TUN / VPN 链路。

证书是设备本地调试凭据。不要把私有密钥或导出的证书文件上传到不可信位置；完成测试后可以删除不再需要的证书和调试资料。

## 配置步骤

### 生成或确认 CA

进入证书设置，先查看当前状态。没有证书时使用 **Generate Certificate** 生成；已有证书时可以使用 **Export Certificate** 导出安装文件。只有在证书损坏、丢失或需要重新建立信任链时才使用 **Regenerate CA**，因为重新生成会使旧的信任链失效。

### 安装并信任

将导出的配置文件交给 iOS 系统安装，然后进入系统的证书信任设置打开 Lemon CA。回到 Lemon 后使用 **Check Trust** 检查系统是否报告根证书已受信任。

“已生成”与“系统已信任”是两个不同状态。前者只说明 Lemon 有证书，后者才说明 iOS 可以用它验证由 Lemon 生成的站点证书。

### 验证链路

完成证书配置后：

1. 启动 TUN / VPN。
2. 在目标 App 中重新触发一个 HTTPS 请求。
3. 回到请求列表，打开该请求并检查 Header 与 Body。
4. 如果只看到连接信息，记录目标域名、App 是否使用证书绑定，以及是否使用了不支持解密的协议。

## 证书绕过与限制

部分 App 会把服务端证书或公钥固定在 App 内，即使系统信任 Lemon CA 也会拒绝连接。此时可能看到连接失败、请求不完整或无法解密。不要把“系统信任成功”理解为“所有 App 都能被 MITM”。

MITM 也不能凭空恢复已经在客户端加密、压缩或编码的业务字段。可以先看 Content-Type、Content-Encoding 和响应状态，再判断 Body 是否适合直接阅读。


## 自动临时绕过

客户端明确拒绝证书时可建立临时绕过。客户端静默关闭时，必须先观察到服务器证书握手消息已经写出，或 TLS 完成后没有应用数据便快速关闭；同一主机、端口、入口和 CA 在 15 秒内出现 3 条不同连接，才暂时绕过 2 分钟。握手成功会清除握手阶段候选。超时、普通网络错误、本地证书错误和明确的 CA 信任错误不会自动变成绕过。静默关闭不等于已证实证书固定。

临时绕过影响后续新连接，无法恢复已经失败的那次握手。有效项不会因访问续期；到期后重新达到条件才刷新。过期历史项不再影响路由；移除自动项后会抑制该主机的自动添加 10 分钟。默认 Apple Push 与 StoreKit 绕过和微信默认项一样通过一次性迁移保存，删除后不因启动重新补回。不同 App 版本的策略可能不同，排查时同时核对 trace 与当前有效记录。

## 安全边界

- 仅在自己拥有或获授权的设备和服务上安装调试证书。
- 调试结束后关闭 VPN / TUN，并移除不再需要的信任配置。
- 请求 Body、Cookie、Token 和证书文件都可能是敏感数据。
- 如果重新生成 CA，重新安装并信任新证书后再开始抓取。

## 故障排查

| 现象 | 优先检查 |
| --- | --- |
| Lemon 显示未信任 | iOS 的证书信任设置是否打开，是否检查了正确的 Lemon CA |
| HTTPS 请求完全没有记录 | TUN / VPN、目标 App 流量路径和网络权限 |
| 有请求但 Body 不可读 | Content-Encoding、二进制类型、证书绑定或协议类型 |
| 已能解密但收到 HTTP 400 | 请求的 Host / :authority、上游 HTTP 协议和重写后的 URL；400 本身不属于证书拒绝证据 |
| 重新生成后全部失败 | 新证书是否重新安装并信任，旧配置文件是否仍被使用 |
