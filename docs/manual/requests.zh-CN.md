# 请求

请求是 Lemon 的流量观察入口。它把经过 Lemon 的 HTTP / HTTPS 事务按时间记录下来，支持搜索、响应类型筛选、收藏、按域名查看，以及打开单条请求的完整详情。

## 什么时候使用

- 想确认某个接口是否真的发出、返回了什么状态码。
- 想比较请求头、响应头、请求体和响应体。
- 想按域名快速找到同一服务下的一组请求。
- 想把一个请求保存下来，之后交给重放或重写继续处理。

请求列表只显示已经经过 Lemon 的流量。列表为空时，先确认 TUN / VPN 正在运行、目标 App 产生了网络请求，并且网络路径确实经过 Lemon。

## 列表中的几种查看方式

### 搜索和范围

顶部搜索框用于按 URL 缩小结果范围。旁边的范围菜单可以在全部请求和收藏请求之间切换。收藏适合保留关键接口，避免每次从实时流量中重新寻找。

### 响应类型筛选

序列视图可以按以下响应类型筛选：

| 筛选项 | 适合查找 |
| --- | --- |
| All | 所有已记录请求 |
| JSON | API 和结构化数据响应 |
| HTML | 页面文档 |
| Image | 图片资源 |
| Script | JavaScript 等脚本资源 |
| XML | XML 或相关接口响应 |
| Other | 未归入以上类别的响应 |

筛选发生在数据加载阶段。切换筛选后，如果当前页面没有结果，先刷新或继续滚动加载，不要把“当前页为空”误判为“没有任何匹配请求”。

### 序列和域名视图

- **序列视图**按时间查看请求，适合还原一次操作的先后顺序。
- **域名视图**按 Host 聚合请求，适合先定位服务，再进入该域名下的具体事务。

请求列表会自动刷新，也支持下拉刷新和清理记录。清理是本地数据操作，执行前确认不再需要这些请求用于后续分析。

## 请求详情应该看什么

打开一条请求后，建议按以下顺序检查：

1. URL、HTTP 方法、状态码和时间，确认是否是目标事务。
2. 请求头中的 Host、Content-Type、Authorization、Cookie 和自定义调试字段。
3. 响应头中的 Content-Type、缓存、压缩、重定向和服务端标识。
4. 请求体与响应体，确认内容是否可解码、是否被压缩，以及是否为 JSON、文本、图片或其他二进制数据。
5. 若是 WebSocket 或 SSE，请进入对应的会话详情查看消息或事件，而不是只依赖普通 HTTP 预览。

HTTPS 内容能否显示取决于 MITM 证书信任、目标 App 的证书绑定和流量是否可被解密。看得到 URL 但看不到 Body，并不一定表示服务端没有返回内容。

## 从请求继续调试

找到目标请求后，可以根据目的选择下一步：

| 目的 | 下一步 |
| --- | --- |
| 只想保存证据 | 收藏请求，必要时导出或通过受控接口读取详情 |
| 想再次执行 | 创建一个重放项目，并在执行前检查 URL、Header 和 Body |
| 想临时修改 | 创建 Rewrite 规则，限制 Host、Path、Method 和阶段 |
| 想长期自动化 | 将逻辑放入脚本或模块，不要手工重复点击 |

重放会重新向目标服务发起请求，可能产生真实副作用。Authorization、Cookie 和请求体也可能包含敏感数据，分享详情前应先脱敏。

## 常见排查

### 列表完全为空

确认 VPN / TUN 已启动，设备确实产生了流量；再检查是否误开了收藏范围、URL 搜索或响应类型筛选。若只缺少 HTTPS Body，优先检查 MITM 信任链。

### 只能看到部分请求

目标 App 可能使用了证书绑定、QUIC / 非 HTTP 协议、WebSocket，或者请求没有经过 Lemon 的当前流量路径。先用一个已知的普通 HTTP / HTTPS 请求验证链路，再缩小到目标 App。

### 需要重新抓取

使用请求设置中的自动刷新开关和清理操作控制列表规模。清理后重新触发客户端动作，观察一条最小、可重复的请求链路。
